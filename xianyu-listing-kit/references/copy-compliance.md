# 文案结构与风险检查

## 输出顺序

先给可直接复制的成稿，再给简短风险说明：

1. 商品标题：优先写清“品类/对象 + 核心用途 + 主要交付形态”，避免关键词堆砌。
2. 开场：用目标用户熟悉的真实场景或麻烦切入，不制造焦虑。
3. 它能做什么：3–7 条具体能力，写动作和结果，不写无法证明的效果。
4. 你会收到：交付物逐项列清，区分资料、工具、服务、更新和答疑。
5. 原理或使用方式：让买家知道怎么用、自己需要做什么。
6. 适合谁 / 不适合谁：帮助用户自我筛选。
7. 需要与限制：设备、系统、网络、账号、版本、学习成本、效果依赖因素。
8. 交付与说明：虚拟/实物、时效、售后边界、数据来源、版权与隐私。
9. 收尾：邀请拍前沟通，不做虚假稀缺或强迫成交。

可以使用少量 emoji 和短段落，保持像真实卖家在解释商品。不要为了套模板而保留空栏目。

## 风险检查

逐句检查以下问题，并在不削弱核心信息的前提下改写：

- 绝对化与保证：如“百分百”“永久”“全网第一”“一定有效”“保证过审”“零风险”。改为可验证的范围、条件或个人体验。
- 收益与结果承诺：不承诺销量、流量、赚钱、排名或审核结果。可以描述工具提供的数据、流程和用途。
- 虚假稀缺与催促：不编造限量、最后一天、马上涨价、多人抢购。
- 误导性交付：标题、主图和正文必须一致；数字资料不能伪装成实物，教程不能描述成代运营或成品软件。
- 资质与授权：不暗示官方合作、平台授权、独家渠道或版权归属，除非用户能证明。
- 商标与品牌：品牌名只用于必要的兼容性、适用对象或事实描述；不使用官方 Logo 冒充官方商品。
- 数据与隐私：说明数据来源与存储位置，不鼓励绕过登录、访问控制、频率限制或抓取非公开数据。
- 售后政策：不自动添加“不退不换”。使用用户确认的真实政策，并提醒其遵守适用法律和平台规则。
- 贬损与对立：把“垃圾、割韭菜、傻瓜”等攻击性表达改成中性、可信的差异说明。

## 风险说明格式

只列真正有影响的项目：

```markdown
## 表达风险自检
- 原表达：……
  风险：……
  已改为：……
- 待你确认：……（事实或政策不明确时）
```

不要声称“无违规词”或“保证通过”。可表述为“已按当前已知风险做保守改写，发布前仍需结合平台最新规则复核”。
